"""

Resulting decision / outcome:
Decision (user-directed): Speech-to-text (ASR) is the primary source of
truth for locating the dialogue, since target videos are not guaranteed to
contain on-screen text. OCR / image-based text extraction is a secondary
pipeline. A deterministic divide-and-conquer ("binary search"-style) frame
search is to be used to avoid linearly scanning every frame, given videos
may be very long.

Prompt #7
--------------------------------------------------------------------------------
Purpose: Asked whether a better algorithm than the user's own "binary
search over frames" idea exists for the OCR localization/refinement
problem.

Exact prompt:
"""
can we do something better than my binary search idea, are there any methods/ algorithms dedicated to optimise this?
"""

Resulting decision / outcome:
No decision in this prompt — a question. The assistant proposed splitting
the problem into (a) global localization, where shot-boundary/keyframe
sampling plus a cheap text-region cascade prefilter replaces fixed-interval
sampling, and (b) local boundary refinement, where a linear scan replaces
bisection because OCR is a noisy oracle a single bisection misread cannot
recover from; noisy binary search was named as the theoretically "correct"
but disproportionate alternative, not adopted. Awaiting confirmation.

Prompt #11
--------------------------------------------------------------------------------
Purpose: Requested a factual efficiency comparison between fallback and
parallel execution of the ASR and OCR pipelines.

Exact prompt:
"""
which do you think would be more efficient, state proper facts
"""

Resulting decision / outcome:
No decision by itself — the assistant provided a factual cost comparison:
ASR is one linear pass over audio only; the OCR pipeline's shot-detection
requires a full video-frame decode pass before any OCR runs. Fallback's
total cost is a strict subset of parallel's, since parallel pays both costs
unconditionally on every run. Conclusion: fallback is more efficient on
total compute, and parallel's only edge (wall-clock latency via
concurrency) isn't justified by any stated latency requirement.
