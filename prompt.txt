Prompt #11
--------------------------------------------------------------------------------
Purpose: Requested a factual efficiency comparison between fallback and
parallel execution of the ASR and OCR pipelines.

Exact prompt:
"""
which do you think would be more efficient, state proper facts
"""

Resulting decision / outcome:
No decision by itself — the assistant provided a factual cost comparison:
ASR is one linear pass over audio only; the OCR pipeline's shot-detection
requires a full video-frame decode pass before any OCR runs. Fallback's
total cost is a strict subset of parallel's, since parallel pays both costs
unconditionally on every run. Conclusion: fallback is more efficient on
total compute, and parallel's only edge (wall-clock latency via
concurrency) isn't justified by any stated latency requirement.

Purpose: Approved implementing two of the three optimization ideas from

Exact prompt:
"""
1. Cache the download across runs (biggest win for you right now)
You've re-run the same URL 3 times today, downloading the full video each time. A cache directory keyed by URL hash (checked before calling yt-dlp, populated after) would make every re-run after the first instant. This doesn't conflict with AGENTS.md's "no video-specific literals" rule — it's generic caching by URL, not hardcoding this video.

2. Fetch audio-only first, video-clip only if/when needed
ASR is the primary path and only needs audio. Right now DEFAULT_FORMAT_SELECTOR in acquisition.py:33 always pulls video+audio muxed together (wv*[height>=240]+wa/w[height>=240]/bv*+ba/b). 3. Parallel fragment downloads
acquisition.py:47 calls yt-dlp with no concurrency flags. Adding -N 8 (--concurrent-fragments) or routing through aria2c (--downloader aria2c --downloader-args "aria2c:-x16 -s16") can speed up fragmented-stream downloads several-fold if the bottleneck is per-connection throughput rather than raw bandwidth. do 1 and 3

Resulting decision / outcome:
Decision (user-directed): implemented URL+format-keyed download caching
(acquire_video() gained an optional cache_dir, keyed by

default 8, configurable via --concurrent-fragments). Idea 2 (audio-only
